Technical Cybersecurity Lab Methodology

Defensive security assessment methodology for controlled laboratory environments

Technical Cybersecurity Lab Workflow
1. Authorized Lab → 2. Observation/Discovery → 3. Traffic/Service Analysis → 4. Vulnerability Scan → 5. Finding → 6. Risk Assessment → 7. Hardening → 8. Retest → 9. Evidence
Mandatory Authorization & Scope Boundaries

All technical demonstrations in CyberAware are restricted strictly to: Localhost (127.0.0.1), Student Virtual Machines, and Intentionally Vulnerable Lab Targets (e.g. Metasploitable, OWASP Juice Shop). Functionality for attacking public websites or unauthorized infrastructure is explicitly omitted.

Kali Linux & Nmap Scanning

Defensive service discovery commands (e.g. nmap -sV -sC 127.0.0.1) identify active ports, service versions, and exposed debug interfaces to formulate port filtering and firewall rules.

Wireshark Traffic Analysis

Packet capture demonstrates cleartext HTTP credential exposure versus encrypted HTTPS communication to highlight why TLS/SSL encryption and secure transmission protocols are mandatory.

OWASP ZAP Web Assessment

Automated dynamic scanning against target web applications detects missing security headers (CSP, HSTS, X-Frame-Options), missing CSRF tokens, and input validation vulnerabilities.

Protected Evidence Storage

Lab evidence logs and screenshots are saved in instance/uploads/lab_evidence/ outside the public web root. Access is controlled by authenticated Flask routes to prevent unauthorized access.
